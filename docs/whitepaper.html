1. Abstract

Corn Store is a public index of free and open-source Android applications distributed through GitHub Releases. It has no submission process, no review queue, and no editorial staff. Applications appear in the index when they publish a signed APK as a GitHub release asset and tag the repository with one of a small set of topics. The index is regenerated daily by an automated scraper. This paper describes the design, the verification model, the failure modes, and the ways in which this approach differs from the submission-and-review model used by F-Droid and IzzyOnDroid.

2. The problem

Android's default distribution channel is the Google Play Store. It requires a developer account, it costs money for commercial publishing, it imposes content policies, and it is the only officially supported source on most consumer devices. For free and open-source software, Play is a poor fit for three reasons:

  • It requires a Google developer account, which many FOSS authors refuse on principle.
  • It does not accept re-uploaded builds, which means fork maintainers and repackagers cannot distribute through it.
  • It does not index applications hosted elsewhere — a release on GitHub and a release on Play are separate artifacts with separate update paths.

The result is that a large fraction of FOSS Android applications are distributed as raw APK files attached to GitHub releases. Users who want them must know the repository exists, find the release, download the APK, and manually install it. There is no discovery layer.

3. How existing stores fail

F-Droid and IzzyOnDroid are the two existing catalogs that try to solve this. Both succeed at their goals and both have documented limits.

F-Droid

F-Droid rebuilds applications from source. This is a strong security property: the APK the user installs is guaranteed to correspond to the public source code, with no developer-supplied binary in between. The cost is that inclusion requires a merge request to a central repository, a review by a human maintainer, and periodic re-review when the application changes. New submissions take weeks to months. Many FOSS Android applications are never submitted and never appear.

IzzyOnDroid

IzzyOnDroid accepts developer-signed APKs rather than rebuilding from source, which lowers the technical bar. It still requires a submission issue, a human review, and compliance with a written inclusion policy. That policy now excludes applications built with the assistance of large language models. Given that a substantial and growing fraction of FOSS Android applications are now developed with LLM assistance, this policy excludes a growing portion of the actual catalog of open-source Android software.

The common failure

Both catalogs are gated by human review. Human review does not scale to the rate at which new FOSS Android applications are produced. It also inevitably encodes the reviewer's preferences, whether those are technical (rebuild from source) or social (no LLM assistance). Applications that do not fit the reviewer's model are excluded regardless of whether they are useful, well-built, or widely used.

4. Corn Store: design

Corn Store inverts the model. There is no submission and no review. The index is populated by a scraper that walks GitHub looking for repositories that match a small set of criteria, and it includes every repository that qualifies. Inclusion is a mechanical property of the repository, not a decision made by a person.

A repository is included when it satisfies all of the following:

  1. It is a public GitHub repository.
  2. It carries at least one of a set of discoverable topics (android, android-app, fdroid, foss-android, kotlin, and others).
  3. Its latest release contains an .apk file as a release asset.
  4. The APK is signed with a release signing key (not the Android debug key).
  5. The release is within a configurable recency window (two years by default).
  6. The APK is under a configurable size limit (100 MB by default).

Nothing else is checked. The scraper does not evaluate code quality, it does not verify that the application does what its README claims, and it does not care how the application was written.

5. The scraper

The scraper is a single Python file (scraper/scrape.py) that runs on a daily GitHub Actions workflow. Its operation is:

  1. Query the GitHub search API for repositories matching each of a set of topics and language filters. Each query returns up to a few hundred repositories.
  2. For each candidate, fetch the most recent GitHub release and check for an .apk asset.
  3. Download the APK, extract metadata using aapt2 (package name, version, minimum SDK, target SDK, application label), and verify the signature using apksigner.
  4. Extract the launcher icon from the APK when it is a raster image. Fall back to the repository owner's GitHub avatar otherwise.
  5. Write a JSON record containing the package name, version, source repository, license, star count, release URL, direct APK URL, APK size, SHA-256 of the APK signature, and — when available — the GitHub-reported download count for the release asset.

The workflow then regenerates a set of derived index files, commits the result back to the repository, and GitHub Pages serves the result statically. The scraper does not run a server and does not maintain a database.

6. The client

The Android client (com.simoesctt.cornstore) is a single screen: a searchable, sortable list of the applications in the index. Tapping an entry opens a detail view with a download button. Tapping download fetches the APK directly from the URL in the index and hands it to the Android system installer.

The client does not host any content. Every APK the user installs comes from the original developer's GitHub release. Corn Store is a directory, not a distributor.

7. Verification and trust

Corn Store does not vet applications. It does verify a small set of mechanical facts, and those facts are the entire trust model:

  • The APK is signed. A debug-signed APK is a development artifact, not a release. The scraper rejects debug-signed builds.
  • The signing key is recorded. The SHA-256 fingerprint of the signing certificate is included in the index. A user who installs an update can compare the new fingerprint against the old one and detect a signing key change.
  • The APK hash is available for verification. The index records enough metadata for a careful user to independently verify the download.

Nothing about this prevents a malicious application from being indexed. A repository can publish a malicious APK, tag it correctly, and it will appear in Corn Store. The scraper is a directory, not a security boundary, and it should be treated accordingly. Users who want stronger guarantees should prefer catalogs that rebuild from source, such as F-Droid.

8. Limits and honest failures

Corn Store does not solve every problem. Known limitations:

  • Only GitHub is indexed. Applications hosted on Codeberg, GitLab, or their own domains are not included, even when they are otherwise identical in form.
  • Only GitHub releases are indexed. Applications that distribute APKs from a website or a package manager are not included.
  • Metadata is only as good as the APK. If the developer does not set an application label, the index shows a fallback. If the developer does not set topics, the scraper may not find the repository at all.
  • Download counts are approximate. GitHub reports downloads per release asset. They are a signal, not an accounting figure.
  • There is no malware scanning. Corn Store does not run VirusTotal or any equivalent. Users who install from the index take the same risk they would take installing the same APK directly from GitHub.

9. Contrast with F-Droid and IzzyOnDroid

F-Droid IzzyOnDroid Corn Store
Inclusion Merge request, human review Issue, human review Automatic, topic-based
Build Rebuilt from source Developer-signed APK Developer-signed APK
Review time Weeks to months Days to weeks Up to 24 hours
LLM-assisted apps Not addressed Excluded by policy Included
App count ~4,000 ~1,000 260 (growing daily)
Malware scanning Source review VirusTotal + source review None

These catalogs are not competitors. F-Droid provides the strongest security guarantees for a curated set of applications. IzzyOnDroid provides a middle ground for developer-signed APKs that pass review. Corn Store provides the broadest coverage with the weakest guarantees. A user who cares about security should use F-Droid. A user who wants to find what exists should use Corn Store.

10. Conclusion

Review-based distribution does not scale to the rate at which FOSS Android software is now produced, and it encodes reviewer preferences that exclude applications regardless of their merit. A scraper-based index with a small, mechanical inclusion criterion covers more of the actual catalog, at the cost of offering no guarantees beyond what a careful user can verify from the APK itself.

Corn Store is one such index. It is not a replacement for F-Droid, and it does not claim to be. It is a discovery layer for the applications that the review-based catalogs do not or will not carry.
